## MaxKey CI/CD 部署测试镜像标签问题修复

### 现象（用户贴 deploy-test 全量日志）
- 所有 MaxKey Pod `ImagePullBackOff`，拉取 `ghcr.io/adminlinzi/maxkey:edge` → `not found`
- GHCR 镜像显示 `unknown/unknown`
- 历史 `sha-*` tag 依旧存在

### 根因
1. deploy-test 的 `kustomize edit set image` 覆盖未做校验，覆盖失败时静默部署了不存在的 `:edge`（base/overlay 默认 newTag=edge，但 images job 只推 `:<version>`）
2. build-push-action 默认附加 provenance/SBOM 证明 manifest，GHCR 渲染为 `unknown/unknown`
3. `sha-*` 是早期成功构建遗留的历史 tag，当前配置已不再生成

### 修复（grill-me 风格逐支分析后落地）
- `release.yml` / `manual-build.yml` 的 `images` job：
  - 加 `provenance: false` + `sbom: false` → 消除 `unknown/unknown`
  - 额外推送 `:edge`（最新构建别名，非 latest/sha-），使 dev overlay 默认 `:edge` 可拉取
- `release.yml` 的 `deploy-test` Pin 步骤：
  - `kustomize edit set image` 覆盖为 `:<version>` 后，增加硬性校验：
    - 部署清单不得含 `edge|latest|sha-` 正则，否则 exit 1
    - 必须含 `ghcr.io/<owner>/maxkey:<version>`，否则 exit 1
  - 校验失败直接终止部署，杜绝静默拉取错误镜像

### 待用户操作
- 提交：`git add .github/workflows/release.yml .github/workflows/manual-build.yml && git commit -m "fix: pin deploy-test to explicit version with verification; drop unknown/unknown via provenance off; add edge alias" && git pull origin main && git push origin main`
- 重打 tag 触发：`git tag -d 4.1.12 && git push origin :refs/tags/4.1.12 && git tag 4.1.12 && git push origin 4.1.12`
- 清理 GHCR 历史 `sha-*`/`latest`/`unknown` tag（用 gh CLI，见对话命令）

## 用户决策：edge 改为 latest（2026-08-27 晚）
- 用户确认：别名用 `:latest`（而非 `:edge`），关键前提是 `:latest` 必须真实推送存在
- 修改点：
  - `release.yml` images job 推送 `:<version>` + `:latest`（原为 `:edge`）
  - `manual-build.yml` images job 推送 `:<image_tag>` + `:latest`（原为 `:edge`）
  - `base/kustomization.yaml` 与 `overlays/dev/kustomization.yaml` 的 5 个 newTag 由 `edge` 改为 `latest`
  - `release.yml` deploy-test 校验正则由 `edge|latest|sha-` 收紧为 `latest|sha-`（仍强制拒绝 latest/sha- 出现在部署清单，确保线上部署用的是具体版本号而非别名）；同时必须包含 `:<version>`
- 逻辑闭环：latest 作为真实存在的兜底别名（dev overlay 默认 / 本地 kubectl apply 可用），但 deploy-test 的 Pin 步骤会覆盖为具体提交 tag，并经校验确认后才 apply；即使 Pin 失败，校验也会拦截 `latest` 并报错终止，绝不会静默用 latest 部署
- YAML 全部校验通过，无残留 `:edge`
- 追加调试输出：`Pin image tags in dev overlay` 步骤现在会打印 `VERSION`、覆盖后的 `kustomization.yaml` 内容，以及构建清单中的镜像标签；任何一步失败都会直接退出并输出关键上下文
