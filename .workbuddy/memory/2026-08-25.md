## MaxKey CI/CD 与 deploy/ 部署体系搭建

通过 grill-me 决策树收敛，为 MaxKey（dromara 上游，GitHub: adminlinzi/MaxKey）建立了完整 GitHub Actions 流水线与独立 `deploy/` 部署目录。

### 关键决策（全部走推荐项）
- 触发策略：tag（纯语义化版本，无 v 前缀，如 `4.2.0`）触发完整发布；PR/main push 仅文档校验 + docker 冒烟 + k8s dry-run。
- 文档：scripts/check-docs.sh 校验 gradle.properties 版本一致性 + README 同步；合并 main 后 git-cliff 回写 CHANGELOG.md。
- 镜像：GHCR（ghcr.io/adminlinzi/*）多架构 amd64+arm64，后端 3 个（maxkey/maxkey-mgt/maxkey-openapi）+ 前端 2 个（maxkey-frontend/maxkey-mgt-frontend）。
- 部署测试：compose 冒烟 + kubectl dry-run；release 时用 kind 临时集群实部署验证。

### 探索发现的隐藏假设（已修正）
- `maxkey-gataway` 是未完成 stub（无 bootJar、网关依赖全注释），排除出镜像集。
- 前端是 Angular 13 → 前端构建必须用 Node 16（非 20）。
- 三个后端 Dockerfile 原用 eclipse-temurin:17，与 JDK 21 构建产物不兼容 → 改为 21-jre。

### 产出文件
- `.github/workflows/{docs,ci,release}.yml`、`.github/actions/build/action.yml`
- `deploy/docker/*`（compose + mysql 初始化 + nginx + 前端 nginx-only Dockerfile）、`deploy/k8s/*`（kustomize base + overlays/dev + kind）
- `scripts/check-docs.sh`、`cliff.toml`、`CHANGELOG.md`、`deploy/README.md`、根 README 增补 CI/CD 章节、`.gitignore` 增补。

### 追加：手动触发构建（2026-08-25 晚）
- 用户需求：少量改代码但不发版本时，可手动触发构建（构建+推送镜像，不创建 Release）。
- 决策（用户确认推荐项）：手动构建 = 构建产物 + 多架构推送 GHCR（标签 `dev-<分支>-<sha>` 与 `sha-<commit>`），**不建 GitHub Release**。
- 实现：
  - `.github/workflows/ci.yml` 增加 `workflow_dispatch` 触发器（手动跑 build+冒烟+k8s dry-run，不推送）。
  - 新增 `.github/workflows/manual-build.yml`（仅 `workflow_dispatch`），输入项 `image_tag`(默认空→自动生成)、`push_images`(默认 true)、`smoke_test`(默认 true)；job: build(算标签+产物+上传) → images(矩阵5镜像，gated by push_images) + smoke-test(gated by smoke_test，镜像本地 `:ci` 构建 + compose 冒烟 + k8s dry-run)。
  - 同步更新根 README CI/CD 表与 `deploy/README.md`（表 + 手动构建用法小节 + GHCR 标签说明）。
- 校验：5 个 workflow YAML 全部通过 PyYAML 语法校验。
- 注意：release.yml 故意不加 workflow_dispatch（会建 Release，与"不发版本"诉求冲突）；manual-build 才是未发版路径。
